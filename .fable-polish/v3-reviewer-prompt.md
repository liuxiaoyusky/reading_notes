# Subagent 2 验收 Reviewer Prompt

发这段给每个 reviewer（验证一章所有 `.md`）：

---

你是寓言大改验收 reviewer，验证 **__CHAPTER_NAME__** 这一章被 Subagent 1 改写的所有 `.md` 文件。

## 章节

- 根目录：`/Users/sky/Documents/github/reading_notes/04-基金从业/02-科目二-证券投资基金/converted/fables/__CHAPTER_NAME__/`

## 任务

逐个文件对照 HEAD 验收。每篇必须通过 8 条硬标准、且不触发任何红线。

## 验收标准（每篇都要过）

### 必须通过（A 大改才算合格）

1. **结构变化**：故事段的句子数 / 行数相对 HEAD 增长 ≥ 50%
   - 例：原文 500 行的故事段，改后必须 ≥ 750 行
   - 例外：原文本身已有 ≥1000 行（极少见）——这种按 B 标准验
2. **对话密度**：每篇至少有 3 处明确的对话（含引号或破折号引导的对话）
3. **场景动作**：每篇至少 3 处具体动作描写（不是抽象"考虑"、"思考"，是"把茶碗往桌上一顿"、"烟杆换了三回"这种）
4. **心理停顿**：每篇至少 1 处人物犹豫 / 沉默 / 未说完的话
5. **收尾非金句**：最后一段不是"XX 的本质是 YY" / "XX 的根本是 YY" / "总之 XX" 形式；最好是具体场景收尾
6. **对照点保留**：💡 对照点表格里的所有故事元素在改后故事里**全部出现**
7. **核心数字/术语/机构名/人名**：与 HEAD 完全一致（不允许改动）
8. **原文定义/对照点/来源行**：与 HEAD 完全一致（一字不动）

### 不可触发（任何一条命中就 FAIL）

- 整篇语气词 > 3 个
- 整篇四字成语 > 3 个
- 整篇破折号 `——` > 3 个
- 三短句排比（连续三个以上短句并列）
- 故事元素→概念对应缺失
- 数字/术语/机构名/人名被改动

## 验收产出

每个文件写一条 verdict：

```
## <相对路径/文件名>
- verdict: PASS / FAIL
- 档位: A（实际）/ B（实际）
- 行数对比: HEAD=500  改后=750  增长=50%
- 对话数: 5 处（≥3 通过）
- 动作数: 4 处（≥3 通过）
- 心理停顿: 1 处（≥1 通过）
- 收尾形式: 具体场景（通过）
- 对照点保留: ✓ 全部 8 个元素
- 核心数字/术语/人名: ✓ 未改
- 不可触发项: 全部未命中
- 失败点（FAIL 时填）：
  - 行数不足：原 500 改后 480（-4%，未达 50%）
  - 收尾金句：最后一段是"XX 的本质是 YY"
  - ...
- 建议修复方向（FAIL 时填）：
  - 加一节具体对话场景
  - 把金句改写为场景
  - ...
```
