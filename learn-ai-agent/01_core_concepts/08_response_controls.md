# M08 · 威胁建模、应急与防御设计

层级：中阶｜学习日：19–21｜先修：M05–M07

全局定位：先看[知识地图](../00_domain_map.md)，指出本模块的先修、当前位置和它为[最终展示项目](../04_projects/SHOWCASE.md)提供的材料，再进入下面的局部概念。模块引入多个新概念时，教学中须逐个补齐“一句话解释、生活类比、技术解释、真实案例、一个练习”。

## 概念解释

### 一句话解释

防御要把预防、检测、响应和恢复串起来，并解释控制的代价与剩余风险。

### 技术解释

威胁建模列出资产、参与者、边界、潜在故障、控制和剩余风险。事件响应围绕识别、遏制、清除、恢复和复盘展开。检测指标只能提示异常；规则缺少业务上下文会误报，阈值和数据缺口又可能漏报。冻结、平台暂停和链级措施对应不同权限，追回不由研究者保证。

## 生活类比

消防设计同时考虑烟雾报警器、防火门、逃生路线和演练。只安装报警器不能灭火，误报太多也会使值班员忽略真正的火情。

## 真实案例

对 C01/C02 做控制映射：区分公告实际措施和自己提出的改进建议；本仓库的模拟数据仅用于检测演练。

案例与原始出处见 [案例索引](../02_case_studies/README.md) 和 [来源台账](../SOURCES.md)。课堂计算和模拟数据不能充当事件证据。

## 练习题

1. 列出研究者、平台安全团队、验证者分别有权采取什么行动。
2. 基于模拟提现数据设计两条告警规则，找一个误报和一个漏报。
3. 写出首 15 分钟的响应清单：谁确认、保留什么证据、如何判断恢复。

把答案写入当日成果；练习工作页见 [模块练习](../03_exercises/M08.md)。先由学习者作答，再检查。

## 输出任务

提交项目 P02：规则说明、告警输出、误报漏报分析及应急卡。

对应具体文件和每日拆分见 [30天路线](../30_day_roadmap.md)。输出必须注明使用真实、历史还是模拟材料。

## 验收标准

- [ ] 规则可以由他人按同一数据重算
- [ ] 至少一个误报和一个漏报场景
- [ ] 恢复标准包含可检查的条件而非“看起来正常”
- [ ] 三道练习合计≥5/6分，且能用自己的话解释一题。

## 检查与复盘

检查每题结论、依据和适用边界，给出0–2分。若答错，先依据实际回答判断“不懂概念 / 不会应用 / 表达不清 / 知识混淆”，再指出证据、计算或权限等具体错误位置；给针对性提示和迁移重试。复盘写入当天日志，每次均更新progress.md并登记复测日；根据薄弱点调整后续任务，保留调整记录，不能用阅读次数替代验收。
