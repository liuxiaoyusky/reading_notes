# M05 · 账户、API 与社会工程风险

层级：基础｜学习日：10–12｜先修：M03、M04

全局定位：先看[知识地图](../00_domain_map.md)，指出本模块的先修、当前位置和它为[最终展示项目](../04_projects/SHOWCASE.md)提供的材料，再进入下面的局部概念。模块引入多个新概念时，教学中须逐个补齐“一句话解释、生活类比、技术解释、真实案例、一个练习”。

## 概念解释

### 一句话解释

账户安全要同时管理人、终端、会话和API权限，单一道认证不能覆盖全部风险。

### 技术解释

攻击面包含人、终端、会话、API、审批和监控。API Key 的实际能力由授权配置决定；只读、交易、提现等权限应分开。多因素认证减少部分账户风险，却不能自动保护已被盗的会话或被入侵的审批链。最小权限、访问范围限制、隔离审批、撤销与告警应配合使用。

## 生活类比

公司门禁卡只该打开工作需要的门。有人冒充维修人员骗你交卡，或在你已经进入办公区后接管电脑，说明多装一道门也不能替代整套流程。

## 练习题

1. 为研究行情、自动下单、财务对账三种角色设计权限；本课程只实际使用公开或离线数据。
2. 对“已有 2FA 就不用监控”提出两个反例和两个补充控制。
3. 给虚构可疑客服消息写一份识别记录，不访问消息中的域名。

把答案写入当日成果；练习工作页见 [模块练习](../03_exercises/M05.md)。先由学习者作答，再检查。

## 输出任务

提交权限矩阵、钓鱼识别表及账户异常应急卡。

对应具体文件和每日拆分见 [30天路线](../30_day_roadmap.md)。输出必须注明使用真实、历史还是模拟材料。

## 验收标准

- [ ] 每项权限都有用途、范围、撤销方式
- [ ] 至少覆盖人、终端、API、会话四个面
- [ ] 不声称 2FA 能杜绝全部盗款
- [ ] 三道练习合计≥5/6分，且能用自己的话解释一题。

## 检查与复盘

检查每题结论、依据和适用边界，给出0–2分。若答错，先依据实际回答判断“不懂概念 / 不会应用 / 表达不清 / 知识混淆”，再指出证据、计算或权限等具体错误位置；给针对性提示和迁移重试。复盘写入当天日志，每次均更新progress.md并登记复测日；根据薄弱点调整后续任务，保留调整记录，不能用阅读次数替代验收。
