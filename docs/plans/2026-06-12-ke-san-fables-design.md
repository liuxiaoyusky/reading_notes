# 科目三寓言故事批量生成设计

## 背景

- **目标**：为 `04-基金从业/03-科目三-私募股权/` 全部 section 生成寓言故事（fable），帮助理解股权投资基金基础知识。
- **当前状态**：`converted/fables/` 目录为空；`converted/sections/` 已有 9 章 34 节 markdown。
- **已有参考**：科目二已完成 173 个 fable，并沉淀了 `regenerate-fables` Workflow 设计文档和脚本框架。

## 目标

生成全部 34 节（预计 40-50 个 fable 文件，因为部分章节会拆分）的寓言故事，统一风格：连续叙事、具体人物对话、概念自然融入情节、附原文定义与对应点表格。

## 核心原则

1. **宁多勿挤**：一个 fable 最多讲 3 个核心概念；概念多的节拆成多篇。
2. **先 Plan 后 Generate**：每个 section 先由 subagent 拆分任务，再逐个生成故事。
3. **风格折中**：沿用 /fable-teacher 的叙事原则（真实困境、四段式、人物对话），但强制附原文定义和对应点表格。
4. **Git 版本控制**：不建备份目录，靠 commit 做版本快照。

## 架构与数据流

```
┌─────────────────────────────────────────────────────────────┐
│              科目三 Fable 生成 Workflow                     │
├─────────────────────────────────────────────────────────────┤
│ 1. Scan                                                     │
│    递归读取 converted/sections/ 下所有 .md                  │
│    排除 00_index.md，得到 34 个 section                     │
│                                                             │
│ 2. Plan（每节一个 subagent）                                │
│    输入：section markdown 全文                              │
│    输出：JSON 任务清单                                      │
│    [                                                        │
│      {                                                      │
│        "conceptFocus": "公司型基金特点",                  │
│        "title": "公司型基金",                             │
│        "filename": "01-公司型基金.md"                     │
│      },                                                     │
│      ...                                                    │
│    ]                                                        │
│    约束：一节最多拆 3 个 fable，每个聚焦 1-3 个核心概念   │
│                                                             │
│ 3. Generate（每个任务一个 subagent）                        │
│    输入：section 原文 + 任务 focus +                        │
│           风格指南 + 第一章 4 篇范例                       │
│    输出：按 Plan 写入 fable 文件                            │
│                                                             │
│ 4. Review（每章抽检）                                       │
│    随机抽 20%（最少 2 个），按质量标准评分                 │
│    不合格 → 重跑该任务                                      │
└─────────────────────────────────────────────────────────────┘
```

## 文件路径映射

```
源文件：
converted/sections/<章>/<节>.md

Plan 输出 → 决定该节生成几个 fable

生成文件：
converted/fables/<章>/<节>/<序号>-<标题>.md
```

示例：
- 源：`converted/sections/03-股权投资基金产品 …/02-公司型基金、合伙型基金与契约型基金.md`
- 可能生成：
  - `converted/fables/03-股权投资基金产品 …/02-公司型基金、合伙型基金与契约型基金/01-公司型基金.md`
  - `.../02-合伙型基金.md`
  - `.../03-契约型基金.md`

## Plan Subagent 规范

### Prompt 要点

```
你是一名教材内容分析助手。请阅读下面这节教材，判断需要拆成几个 fable。

规则：
- 一节最多拆成 3 个 fable；
- 每个 fable 聚焦 1-3 个核心概念；
- 优先按“自然段落/子标题”拆分；
- 不要为了拆而拆，概念少的节就 1 个 fable。

返回 JSON：
[
  {
    "conceptFocus": "这个 fable 要讲的核心概念（一句话）",
    "title": "用于文件名和标题的概念名（4-10字）",
    "filename": "01-标题.md"
  }
]
```

## Generate Subagent 风格指南

### 硬性规则

1. **一个完整故事**：开头→发展→高潮→结局，禁止条目式结构。
2. **具体人物**：有名字或具体身份，有对话和互动。
3. **概念融入情节**：概念在角色经历中自然呈现，不是讲完故事再贴概念。
4. **故事占全文 60% 以上**。
5. **600-1200 字**。
6. **聚焦 1-3 个核心概念**，不贪多。

### 输出格式

```markdown
# <原节标题>

## <emoji> 寓言故事 —— 《<4-6字故事名>》

<完整故事>

---

**📖 原文定义**

> 直接引用教材原文的定义

**💡 对应点**

| 故事元素 | 概念对应 |
|---------|---------|
| ... | ... |

---

> 📝 来源：科目三 · 第X章第X节 · <标题>
```

### 风格范例

每个 Generate subagent 都会收到第一章 4 篇作为范例：

1. `converted/fables/01-股权投资基金概述 …/01-股权投资基金的概念和特点/01-股权投资基金的概念和特点.md`
2. `converted/fables/01-股权投资基金概述 …/03-股权投资基金市场参与主体/01-股权投资基金市场参与主体.md`
3. `converted/fables/01-股权投资基金概述 …/04-股权投资基金的起源和发展/01-股权投资基金的起源和发展.md`
4. `converted/fables/01-股权投资基金概述 …/05-股权投资基金对经济高质量发展的作用/01-股权投资基金对经济高质量发展的作用.md`

## 质量控制

### 第一阶：Generate Subagent 自检

输出前必须回答：

- [ ] 是否是一个完整的故事（开头→发展→高潮→结局），没有条目式结构？
- [ ] 是否有具体人物（有名有姓/有身份），有对话和互动？
- [ ] 概念是否自然融入情节中？
- [ ] 故事是否占全文 60% 以上？
- [ ] 故事长度是否在 600-1200 字之间？
- [ ] 是否只聚焦了 1-3 个核心概念？

### 第二阶：每章抽检

- 每章完成后，随机抽取 20%（最少 2 个）fable；
- Review subagent 按以下标准评分：
  - 故事完整性（20%）
  - 人物对话（20%）
  - 概念融入（30%）
  - 原文定义 + 对应点格式（20%）
  - 长度适中（10%）
- 评分 < 70 视为不合格；
- 单章不合格率 > 30% → 整章重跑；
- 单章不合格率 ≤ 30% → 仅重跑不合格的。

### 第三阶：人工终审

Workflow 跑完后，用户可抽查任意 fable，不满意可单独重跑。

## 错误处理

- **Plan subagent 失败**：重试 1 次，仍失败则记录到 `batch-task.md`，跳过该节；
- **Generate subagent 失败**：重试 1 次，仍失败则记录；
- **Review 抽检不合格**：自动重跑对应任务，最多重试 2 次；
- **写入失败**：记录错误，人工处理。

## 版本控制与进度追踪

### Git 策略

- Workflow 运行前，先 commit 当前状态（包含第一章 4 篇样例）；
- 每章生成并抽检通过后，commit 一次；
- 如有整章重跑，先 revert 该章文件到上一 commit，再重跑；
- 全部完成后，最终 commit。

### 进度文件

- `converted/fables/batch-task.md` 记录：
  - 每章状态：pending / planning / generating / reviewing / done
  - 失败任务和重试次数
- 每章完成 commit 一次，日志写进 commit message。

## 与科目二方案的主要区别

| 维度 | 科目二 | 科目三 |
|---|---|---|
| 拆分策略 | 按现有 fable 文件一对一重生成 | Subagent 自动拆分，每节 1-3 个 fable |
| 范例来源 | 保留现有 3 篇golden sample | 用第一章 4 篇新写样例 |
| 备份方式 | `fables.backup.YYYYMMDD` | Git commit |
| 输入源 | 已有 fable 推断源 section | 直接扫描 section 目录 |
